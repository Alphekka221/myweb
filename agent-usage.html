使用方式

目前的使用方式是通过对话下发指令：把在其他工具（Codex、Trae）中形成的构想和结果发给 Workbuddy， 由它来完成内容整理与最终产出。本次的具体任务，就是把「学生教师知识库」的项目构想，以及 Trae 的使用截图， 整理制作成当前的这份 HTML 汇总网页。

💭 个人使用感受

速度比较快，而且输出比较清晰，很好用。

定位：汇总与交付层 —— 输入是各处积累的设想与素材，输出是结构化、可直接查看分享的成果文档。

使用情况（来自截图）

在 Trae 中向 Agent 提问了一个开放性知识问题（"询问有关雷达系统的一些基础知识，例如不同天线结构的特点"）， Agent 花费约 6 分 27 秒完成任务，并给出了结构化的回答：

  • 分层组织答案：按「雷达基本原理 → 系统组成 → 天线类型与优缺点总结」三大块展开，条理清晰。
  • 表格化呈现：用表格把"测什么、物理量、公式近似、关键部件"对应起来（如距离 R = c·Δt/2、速度、角度测量等）。
  • 动态 Widget 渲染：Agent 直接生成了 HTML 动态图（Widget 3 dynamic diagram），可实时预览雷达系统组成图，并且代码可展开查看、支持复制。
  • 自适应主题：生成的 Widget 内置了 light / dark 两套配色变量，能跟随界面主题切换。

特点：擅长把知识类问答讲清楚、画出来——文字、表格、动态图结合，适合用来做知识梳理和演示。

Codex

项目定位

在 Codex 中完成了「学校知识库系统」的初步设想——一个让学生查知识、学知识、 让教师管知识、做检查的平台。目前仍处于构想阶段，尚未进入开发。

🎓 学生端：查知识、学知识

  • 按关键词、课程、年级或知识点搜索
  • 查看知识讲解、相关资料、例题和引用来源
  • 收藏内容，记录自己的学习进度
  • 用日常说法提问，系统从学校整理的资料中找答案并标出出处

🧑‍🏫 教师端：管知识、做检查

  • 上传或整理讲义、题目、参考资料
  • 添加课程、年级、章节等标签，方便检索
  • 布置小测验或检查任务
  • 查看完成情况与薄弱知识点分布

"检测"的两层含义

教师端的"检测"包含两件事：① 检测学生掌握情况（测验、答题统计）； ② 检查资料内容质量（是否正确、完整、适合发布）。第一版不把两者做复杂。

切入点：先回答三个问题

  • 谁会用？例如某门课的学生和任课教师。
  • 要查什么？例如教师提供的讲义、知识点说明和练习题。
  • 查完要做什么？例如学生找到答案后完成练习，教师看到完成情况。

第一版核心流程

  1. 教师上传资料，填写标题、课程、章节等信息
  2. 学生用关键词搜索资料
  3. 学生查看资料和来源
  4. 教师发布简单练习，查看答题结果
💭 个人使用感受

响应比较快速，而且讲解得很清楚，思路容易跟上。

后续规划：等核心流程跑通之后，再考虑自然语言问答、智能推荐、自动批改、学情分析等进阶功能。
